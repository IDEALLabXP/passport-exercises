# Mission: Create A Recoverable Project Handover

## Outcome

Another authorized researcher can locate the code, data, environment, decisions,
results, owners, and unresolved risks without using your personal account or
machine.

## Concept

Projects often fail operationally after a student leaves even when files still
exist. A handover establishes ownership, provenance, reproduction, access, and
cleanup rather than transferring an unexplained directory.

## Worked Example

Another authorized person could locate, verify, rerun, and safely retire the fictional project without hidden personal dependencies.

A correct example uses these decisions:

- **What is a successful handover?** An authorized successor can locate, verify, rerun, and maintain or retire the work.
- **How are credentials handled in a handover?** Rotate or provision access through approved channels; never place secrets in the document.

## Common Trap

Listing a folder without naming its owner, code revision, environment, access boundary, or retention decision.

## Your Action

Prepare the practice folder, then complete
`workspace/handover/project-handover.md` with fictional ownership, locations,
code revision, environment, access, retention, and deletion decisions. Replace
every `REPLACE_ME` field. Never use real project details in this public fixture.

The passport presents the structured questions and required confirmation in the
browser. Do not create or edit a submission JSON file by hand.

## Check Your Work

Use **Check my work** before submitting. The local verifier checks only the
bounded activity named above. A score of 80% is required, and every
safety-critical question must be correct. Failed attempts provide targeted
feedback and can be retried without penalty.

## Understand Before Accepting AI Output

An agent may format an inventory but cannot certify that paths exist, access
works, results reproduce, or disposal is approved. A person verifies each item.
